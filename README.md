# BangsKinesis

DuckDuckGo-style `!bangs` on **any** search engine, for Chrome and Firefox, using the
[Helium bangs collection](https://services.helium.imput.net/bangs.json), cached locally.

## Usage

- **Plain search:** type `!dev react` (or `react !dev`) in the address bar. The search to your default
  engine (Google, Bing, Brave, Ecosia, Yahoo, Startpage, Qwant, Yandex) is redirected to DevDocs
  *before* the engine is contacted. `!yt` with no terms opens the site root.
- **Keyword mode (live preview):** type `!` then <kbd>Space</kbd>. The browser shows its keyword chip, and
  the dropdown previews where the bang goes ("DevDocs — search devdocs.io for react"), with
  prefix suggestions while you type the trigger. Extensions can't draw a pill inside the address
  bar text itself the way Helium does natively, so this is the closest equivalent.
- **Options page:** collection status, manual refresh, per-engine toggles, and a "try a bang" box.

## How it works

| Piece | Where |
| --- | --- |
| Lenient JSON parsing (comments, trailing commas), trigger index | `lib/bangs.ts` |
| Bang extraction (first/last token) | `lib/query.ts` |
| URL building (Kagi `fmt` flag semantics) | `lib/url.ts` |
| IndexedDB cache keyed by trigger (about 1 ms lookups) | `lib/store.ts` |
| Bundled snapshot seed + ETag conditional refresh every 6 h | `lib/data.ts`, `scripts/fetch-bangs.ts` |
| DNR regex rules → `redirect.html#<url>` | `lib/engines.ts`, `lib/rules.ts`, `entrypoints/redirect/` |
| Omnibox keyword mode | `entrypoints/background.ts` |

Unknown bangs (e.g. a literal `!important` search) bounce back to the engine with `&bk=0`, which a
higher-priority DNR `allow` rule exempts.

## Development (Bun)

```bash
bun install
bun run dev            # Chrome with hot reload
bun run dev:firefox
bun test               # unit tests
bun run compile        # typecheck
bun run build && bun run e2e                   # Chrome end-to-end (Playwright Chromium)
bun run build:firefox && bun run e2e:firefox   # Firefox end-to-end (WebDriver BiDi)
bun run zip && bun run zip:firefox             # store packages in .output/
```

`bunfig.toml` refuses package versions published less than 7 days ago (`minimumReleaseAge`).
Icons are generated by `bun scripts/gen-icons.ts`.
